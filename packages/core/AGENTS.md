# @nipakk/core

Pure TypeScript business logic: the package catalog and everything Homebrew

## Structure

```bash
packages/core/
├── src/
│   ├── catalog.ts          # Catalog types and accessors
│   ├── catalog.gen.json    # Generated by `vpr catalog:sync`, don't edit
│   ├── brew.ts             # Install command and Brewfile generation
│   └── selection.ts        # Selection <-> URL value, validated against the catalog
└── scripts/
    ├── catalog.config.ts   # Category rules (the config to edit)
    └── sync-catalog.ts     # Categorises top installs, writes catalog.gen.json
```

## Catalog

- Homebrew has no categories, so each category is a description rule (regex) in `catalog.config.ts`. No package is listed by hand
- `vpr catalog:sync` reads Homebrew's 365 day install analytics, walks the top `CANDIDATES_PER_KIND` casks and formulae, and files each under the first matching rule until a category holds `PACKAGES_PER_CATEGORY`. Packages show as their brew token, descriptions come from Homebrew
- Skipped: taps (would break the generated command), deprecated or disabled packages, and extra versions of one package (`python@3.13` when `python@3.14` ranks higher)
- A weekly workflow (`.github/workflows/catalog.yml`) runs the sync and opens a pull request when rankings change

## Conventions

- No React, no DOM, no network in `src/` (enforced by `tsconfig.json`)
- Anything that ends up in a shell command must come from the catalog, never from user input
- See [testing](../../docs/testing.md)

## Using in Other Packages

```ts
import { toInstallCommand } from '@nipakk/core/brew';
```
